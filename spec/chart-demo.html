Charts that follow the table

Select a portfolio, category, product or index in the Drivers & Differences table; the cards that follow the selected row retitle to it. The table stays the primary comparison surface; the chart explains the selected row over time or across scenarios.

Historical analysis starts with growth of an investment. Forward-looking analysis offers projections and scenario comparisons. Portfolio colours stay consistent, and the chart legend controls which allocations receive emphasis independently of table selection.

Try the workflow. Select Public Equity, toggle portfolio names in the legend, then switch to Forward-looking. Compare standalone growth with weighted portfolio contribution, change the horizon, and open Scenarios to compare each portfolio’s base and scenario values side by side.

Interaction requirements

  • Historical: retain every compared allocation as a visible line. Clicking a legend entry adds or removes it from the emphasized set; muted lines are still identifiable by colour and the legend.
  • Projection: show one small chart per emphasized allocation, with a central path and uncertainty band. Every chart uses the same time and value axes for the selected row and value basis.
  • Value basis: standalone growth starts at £100. Weighted contribution starts at the category’s share of a portfolio initially worth £100; a 55% Public Equity category starts at £55.
  • Scenarios: show base and scenario values beside each other for each allocation. Name the assumption set, state its scope, and label units.
  • Persistent context: switching historical/forward-looking, metrics, or chart views retains the chosen row and emphasized set. The table and allocation builder stay available.

Acceptance checks

  • Select Public Equity, then Investment Grade Fixed Income: the chart title, values, and contribution weights update without changing selected portfolios.
  • Toggle Core and Income in the legend: those lines become muted or emphasized; the corresponding projection charts appear or disappear.
  • Switch Public Equity to portfolio contribution: each projection’s starting value equals that allocation’s Public Equity weight, with a clear “per £100 initial portfolio” label.
  • Change the horizon: every projection chart uses the same selected horizon and matching axes, including when only one chart is shown.
  • Remove all emphasis: historical lines remain visible, while projections show a clear instruction to select a portfolio.
  • All controls work with a keyboard; chart titles, accessible descriptions, and numerical outcome summaries communicate meaning beyond colour.

User story. As a portfolio manager, I can inspect a selected category’s history and plausible future outcomes without losing my comparison. As an analyst, I can hold the scale and assumptions context constant while comparing several allocations.

Chart boundaries, data semantics, and proposed defaults

The example uses deterministic placeholder paths and illustrative bands. The 80% band and available horizons are proposed interface defaults; they are not confirmed model settings, calibrated probabilities, or promises of investment performance. A production interface must display the model’s supplied uncertainty definition and horizon.

Chart type follows the metric. Return/value projections can use growth paths. Historical risk contribution uses a percentage or volatility-contribution time series; factor exposure uses beta/exposure units. Do not convert a beta, allocation weight, or risk contribution into “growth of £100.” If a forward projection is unavailable for the selected metric, explain that state and offer the compatible scenario view.

Historical plots use common inception by default, while distinguishing actual history from backtests. Missing observations create visible gaps rather than invented interpolation. The product should offer shared tooltips and a resizable table/chart split as proposed enhancements. This compact demo focuses on legend emphasis, value basis, horizons, and scenario comparisons; it does not implement pricing, risk modelling, historical reconstruction, or the application-wide table selection.
