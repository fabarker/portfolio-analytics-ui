Scenario assumptions: edit the inputs, see the difference

Open the scenario drawer from the analytical workspace. Edit capital-market assumptions at factor, asset-class, or holding level in a spreadsheet-style matrix. The base case stays visible alongside scenario results; users decide what the resulting differences mean.

Why this layout

The matrix gives researchers direct control without adding permanent complexity to the main table. A drawer keeps the edited assumptions beside their consequences. Selectable scope makes it explicit which of the compared allocations receives the experiment.

Proposed detail Multiple named scenarios, drawer resizing, per-cell resets, and override precedence are working assumptions from the predicted answers. They are reviewable design proposals, not earlier confirmed decisions.

Try this: change the Equity factor expected return from 7% to 5%, uncheck Portfolio B, and compare their base/scenario columns. Then select Equity–Credit in the correlation grid and change it to 0.80 using the pair editor. Use Overrides only to inspect your experiment.

How this example calculates its numbers

This is a small interactive illustration, not an institutional analytics engine. Each placeholder allocation contains Equity, Bonds, and Credit. Expected return is the weighted sum of their assumed returns. Volatility is the square root of the weighted covariance calculation using the three-asset correlation matrix. In this example, beta multiplies an asset's risk loading; it does not alter its expected return.

Variance is entered in percentage-points squared (%²): 225 %² corresponds to 15% annual volatility. A return override of 5 means 5%, not 0.05%. The “Global equity fund” row acts as the entire equity sleeve's holding proxy in this small demo.

Proposed inheritance: an explicit holding override wins over an asset-class override, which wins over a factor override. A reset removes that override and resumes inheritance. The production UI must expose the effective source and the backend's actual methodology; this hierarchy and proxy are only demonstration assumptions.

Interaction requirements

  • The drawer retains its scenario and scope when closed. Show the scenario name and number of overrides in the workspace header.
  • Support explicit overrides at multiple levels, a platform baseline, effective-source labels, reset controls, and an override-only filter.
  • Show factor, asset-class, and holding names with their level; beta fields must identify the factor to which the exposure applies in production.
  • Scope defaults to all compared allocations. Unscoped portfolios remain clearly labelled “Base only.” Changing scope never alters their saved allocations.
  • Changes autosave within the workspace. This document stores its demonstration state only in this browser; production autosave must synchronize the workspace's data.

Acceptance examples

  • When Equity factor return becomes 5%, A's scenario return changes while its base return remains fixed.
  • When B is outside the scope, B's scenario column equals its base column and reads “Base only.”
  • Entering correlation 1.2 produces a range error and preserves the previous valid value; a non-positive-semidefinite matrix is also rejected with a useful explanation.
  • Resetting one override resumes its inherited value. Resetting all overrides restores both assumptions and correlations to the base case.
  • With the drawer closed, scenario results and state remain visible. Reloading restores valid browser demo state where local storage is available.
