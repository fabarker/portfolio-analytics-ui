Entry behavior

A blank draft remains valid for editing even at 0% allocated. Templates set category weights as explicit holdings of each category’s index basket, which products can replace; clones copy holdings and sleeve tags. Imports first expose mappings, unmatched rows and totals; users resolve errors before loading an allocation. Never silently discard unmatched holdings.

Search behavior

One search accepts funds, ETFs, indices, securities, sleeves and portfolios. Each result carries type and identity metadata. A product result exposes its asset class and therefore its home category; adding asks for the weight, files the product in the category whose + was used and raises that category’s weight by it. A sleeve result opens the apply flow. The example inspects fictional identities only.

Import example boundaries and acceptance

This compact demonstration accepts category weights only: one row per standard category, as a percentage of the total portfolio. Production imports must also carry products with identifiers and weights; the template and supported formats are proposed. Short or leveraged imports must require the portfolio capability to be enabled, without imposing risk limits.

  • A duplicate, unknown, non-numeric or missing row produces a specific error naming the row.
  • Totals below 100% are allowed and displayed as incomplete. Negative or above-100% imports are blocked in this simplified long-only import path.
  • Input errors preserve the existing draft; a successful preview shows the category weights, the allocated total and the unallocated amount.

Fixed snapshots

Snapshots are fixed copies. Restore creates a new editable draft state; it does not mutate the snapshot.

State transitions and acceptance criteria
  1. A valid edit updates the working draft immediately and starts recalculation. Autosave and calculation are distinct statuses.
  2. While calculating, keep the last valid value but label it “Previous result · updating.” Do not present it as current.
  3. When the latest calculation completes, replace values and briefly highlight changed cells. An older response must never overwrite a newer edit. Each card does this independently.
  4. On failure, preserve the draft and last valid result, label the stale result, and offer retry. Saving can succeed even if analysis fails.
  5. Unavailable is not zero. Missing-data and empty states identify what is absent and the supported next action.
  6. Undo restores the prior draft. Snapshots stay fixed. Product history depth, collaborator behavior and recovery retention require a separate confirmed policy.
