Understand the allocation.
See the difference.

An interface specification, with a working mockup, for building, testing and comparing multi-asset portfolios in one continuous workspace.

The allocation is a tree of categories, shared by the workspace, holding products and indices; each category’s weight is the sum of its holdings. Sleeves save reusable subsets of it. The analysis is a collection of cards around the Drivers & Differences table. Users edit, observe, test assumptions and inspect the evidence—without the interface proposing investment actions.

One workspace, four jobs

BuildWorkspace categories, products and indices, quick add, universal search
ReuseSleeves: saved product subsets in a shared, versioned repository
TestLive analytics, editable assumptions, scoped scenarios
CompareCards from a repository, one shared context bar, aligned rows

The allocation stays in context while the cards change. Complexity appears only when it serves the question being investigated.

How to use this document

Read the intent and layout, then operate the mockup. Each feature section explains its purpose, interaction, expected states and acceptance criteria. The final sections separate the proposed delivery order from decisions still needing product input.

Mockup and example boundaries

The mockup (workspace/index.html, beside this document) runs locally on fictional data behind a documented data-access layer. The scenario, chart, entry and state examples in this document are independent teaching examples; changes do not synchronize between them or with the mockup. Analytics demonstrate UI behavior, not production financial calculations. No external accounts or services are contacted.

What the Venn references teach us

Observed in supplied screenshots

Adopt the persistent context; adapt the analytical organization to this product’s narrower focus.

Adopt

The visible hierarchy makes portfolio structure legible. Inline weight fields shorten the path from an investment idea to a test. Persistent benchmark and date context help users interpret every result.

Adapt

Replace the performance-summary starting point with the Drivers & Differences table as the anchor card. Use a Historical / Forward-looking switch in a shared context bar instead of permanently doubling columns. Keep historical and forecast context equally accessible as cards.

Improve for this brief

Make the split adjustable, retain four to six comparison allocations, label live versus fixed versions, and replace explicit save dependence with continuous draft autosave. Let each category hold indices and products alike, its weight always the sum of its holdings, and let a proven set of products be saved as a sleeve and reused.

Factor analysis reference and interpretation

The reference puts factor names, signed bars and numerical values together. This is a useful model for readable, evidence-based comparison.

Our adaptation keeps the exact values in the integrated table, with multiple selected factor columns under each allocation. A Factor exposures card that follows the selected row supports visual investigation without replacing the table.

The smaller supplied screenshot also shows a factor contribution popover. Its drill-down idea is useful, but a card the user can place and keep gives more room and avoids competing with the scenario drawer.

These are observations from static screenshots, not claims about every capability or behavior in Venn.
